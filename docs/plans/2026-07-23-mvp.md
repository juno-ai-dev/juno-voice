# Juno Voice MVP implementation plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Ship and live-smoke a Juno Voice CosmWasm contract plus a Juno Design System-compliant web client for requests, fixed-snapshot voting, lifecycle history, and delivery evidence.

**Architecture:** A single Rust contract owns canonical records and queries Juno `x/voting-snapshot` through custom bindings. A TypeScript client reads RPC directly for detail and may use a derived indexer for search. The first implementation stays non-binding and excludes arbitrary execution, payouts, and comments.

**Tech stack:** Rust/CosmWasm, `cw-storage-plus`, CW2, Juno custom query bindings, TypeScript, React-based framework selected after inspecting current Juno app precedent, CosmJS, Juno Design System.
